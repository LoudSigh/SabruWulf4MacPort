# Run and observe on this Mac

**Double-click [Run Sabre Wulf Preview.command](../Run%20Sabre%20Wulf%20Preview.command)** in Finder. Alternatively, in a terminal at the repository root:

```sh
./Run\ Sabre\ Wulf\ Preview.command
```

Allow the first build to finish. The launcher checks the hashes of your existing `SNAPSHOTS/Snapshot.z80`, `SNAPSHOTS/Snapshot_GamePlay.z80` and backup `ROMS/48.rom`, generates two PNGs, a 16×16 room-type overview, measured room bounds, **private background and sprite atlases**, fourteen recorded input replays and five moving-entity comparisons under **ignored, private** `reverse_engineering/private/`. It verifies covered RGB pixels in the captured room (**29,056/29,056**), north-exit room (**28,544/28,544**) and west-exit room (**30,720/30,720**), verifies the recorded player-mask placement in **489/500** Q/W/E/R/T frames (the remaining 11 W frames have overlapping graphics/attributes), and checks **256/256** west, **100/100** T-key and **190/190** for each pre-contact T/no-T/A control RAM/screen hashes against the unmodified emulator. It builds the native macOS app and opens the images in Preview, the map in a browser, and the app. It does not move or modify the snapshots, copy original media into the app, or commit any disassembly. If a prerequisite is missing or a hash differs, it stops with an explicit error instead of opening a misleading result.

## What you will see

- **Preview:** two authentic but **static** 256×192 frames generated from your 48K snapshots: the menu and one jungle gameplay frame. Zoom the images to inspect them; they are not playable.
- **Browser:** a **private 16×16 world-type overview**, derived from the two matching snapshots. Repeated numbers/colors identify reusable room templates, not full original room art. It is structural and not playable.
- **SabreWulfMac:** an **interactive prototype** with independently authored maze, movement, items and enemies. Use the on-screen arrows (or keyboard arrows/WASD), Pause and Reset. This main game is a placeholder, **not** a finished recreation of the 1984 game.
- **Inside SabreWulfMac:** expand “Explore source-backed 16 × 16 world” below the prototype controls, click “Import your private world data”, and select `reverse_engineering/private/snapshot-803e4197989c-world-v2.json`. You can browse all 256 original room positions with placement markers and measured orange background outlines. Select **Start measured movement (partial)** to move the pink marker through imported room geometry at 50 frames per second (or step one frame); pick a held Q/W/E/R action, then Play/Pause/Reset. This starts from the in-game capture and includes static collision plus the measured north passage and return; unverified exits pause with an error. It is separate from the placeholder main game and lacks combat, enemies, quest and complete art.
- Import `reverse_engineering/private/replay-upper-exit-180.json` with “Import a private gameplay replay (optional)” to scrub the **recorded** W/E path (cyan marker) that crosses from room ID 168 to room ID 152 at frame 68; alternatively choose `reverse_engineering/private/replay-q-100.json` for a shorter leftward path. The measured preview and the recorded replay have distinct markers and a frame-indexed position comparison. To reproduce the W/E path, start the movement preview, advance 20 frames with None, hold W for 10 frames, then hold E through frame 180. This is only a bounded playable movement slice, not a full native game simulation.
- Select `reverse_engineering/private/replay-round-trip-200.json` to scrub a second path that returns to room ID 168 at frame 88 (X=121/Y=190), then rebases to X=120/Y=39 at frame 94. Reproduce it with None for 20 frames, W for 10, E through frame 75, and R through frame 200; it too is only a verified movement slice.
- Select `reverse_engineering/private/replay-west-exit-256.json` for the **legacy absolute-boundary** path into room ID 151 at frame 226. Reproduce it with None for 20 frames, W for 10, E through frame 100, None through frame 180, then Q through frame 256. Native static movement matches its room/X/Y, but an enemy encounters the player in the unmodified emulator at frame 163. **For a reference-timed replay of the same input, import `reverse_engineering/private/replay-west-reference-256.json` instead.** That replay matches every RAM frame of the full emulator and shows the damaged actor staying in room 152. The native preview cannot match it because enemy interactions have not been ported.
- With the matching legacy west replay, select **Import private enemy route comparison (optional)** and choose `reverse_engineering/private/west-entity-trace-v2.json`. At frame 163 the orange ring shows a moving entity at X=161/Y=130 in the old absolute runner, while the purple ring shows X=104/Y=135 in the unmodified emulator, near the player at X=121/Y=126. With the reference-timed west replay, choose `reverse_engineering/private/west-entity-reference.json` instead; orange/purple positions align. Rings appear only while the entity slot is active; numeric positions remain visible. This is **read-only**, not native enemy AI. Mismatched timing modes or actor paths are rejected.
- Select `reverse_engineering/private/replay-east-return-279.json` to scrub a **provisional legacy-timing** return from room 151 to 152 at frame 246, rebasing to X=0/Y=126 on frame 253. Its Q action ends at frame 226 and W begins at frame 233; see [east-return-schedule.json](../reverse_engineering/analysis/east-return-schedule.json) for exact intervals. Native and absolute-boundary CPU actor states match through frame 279; a moving entity damages the source player at frame 280. The aligned reference already follows a different enemy route, so this is not full-game parity.
- Import `reverse_engineering/private/replay-fire-reference-100.json` to scrub the **reference-timed T-key observation** (T held from zero-based frame 20 to 39). The displayed actor-state number changes during the action while room/X/Y remain 168/57/112; all 100 RAM and screen hashes match the unmodified emulator. These numbers are observations, not a native attack, hit detection or complete animation.
- To compare T near a moving entity, import `reverse_engineering/private/replay-fire-before-contact-190.json` (T held at frames 145–169) and its matching `reverse_engineering/private/trace-fire-before-contact-190.json`. Then import `replay-no-fire-encounter-190.json` and `trace-no-fire-encounter-190.json` from the same private directory to contrast frame 163. With T, the source player stays at X=121/Y=126 while entity slot 12 is at X=86/Y=135; without T it approaches X=104/Y=135 and the player's state changes at frame 164. Each path independently matches **190/190** RAM and screen hashes. **Do not infer a general hitbox or enemy kill rule:** T changes RNG by frame 146, which explains the first enemy-direction difference at frame 156 through a random-direction branch.
- An unrelated-key timing control is available as `replay-unrelated-a-control-190.json` with `trace-unrelated-a-control-190.json`. A from frames 145–169 delays the player's damage state until frame 170, but does **not** reproduce the T-specific enemy state change at frame 156. This guards against attributing every difference to a sword hit rather than changed input/CPU timing.
- Four further private replays named `hold-q-150.json`, `hold-w-150.json`, `hold-e-150.json` and `hold-r-150.json` compare 150 frames each. Starting from frame zero, leave None selected for 20 frames and hold the matching key for the remaining 130. The native movement subset matched room/X/Y for all 980 independently checked frames across these four holds and the two verified multi-key paths, plus 535 provisional west/east-path frames; other interactions are not validated.
- If you have already made a permitted local copy of the backgrounds, choose “Preview private background images” and select `SNAPSHOTS/backgrounds/`. The preview is **optional**, partial and approximately blended; the app never bundles those PNGs.
- Or use the **snapshot's own** background shapes: choose “Import private snapshot backgrounds (optional)” and select `reverse_engineering/private/snapshot-803e4197989c-background-atlas-v1.json`. The world explorer draws all 41 verified bitmap shapes at **direct screen X/Y** as mint-colored 1-bit source bits. Optionally enable “Preview 48K attribute colors (approximate)” to inspect the bitmap-complemented screen ink/paper result. The captured room's **covered static pixels match exactly**; uncovered pixels, dynamic sprites, FLASH and other rooms are not certified. This supersedes the downloaded PNG overlay while selected. No source art is in Git or the bundle.
- To inspect two privately verified Sabreman silhouettes, choose “Preview private sprite silhouettes (optional)” and select `SNAPSHOTS/graphics/downloaded/`. The app accepts the locally supplied `10.png` and `15.png` sample dimensions and shows thumbnails only; it does not copy them into the build or claim animation/palette fidelity. The room viewport keeps the Spectrum's 4:3 proportions.
- For the **snapshot's own** bitmap records instead of downloaded PNGs, select “Import your private snapshot sprite atlas (optional)” and choose `reverse_engineering/private/snapshot-803e4197989c-sprite-atlas-v1.json`. Drag the sprite ID slider through 0–195 to see a cyan, independently drawn, screen-up 1-bit silhouette. Fourteen IDs refer to an empty sentinel. Shapes are local-only; color and actor-state mapping outside the checked replays remain unverified.
- With that atlas imported, scrub `replay-fire-reference-100.json` to display the decoded silhouette for each recorded player actor-state ID beside the numeric state, and optionally in white at the actor's observed X/bottom-Y in the room. The initial capture also has a verified player mask when no replay is selected. The room overlay is hideable and **not** original dynamic overlap/combat: the local source verifier checks **489/500** unobstructed Q/W/E/R/T frame rectangles exactly, with 124 pixels differing across 11 W frames.

Use **Command-Tab** to switch between the app and Preview. The images, compiled local snapshot exporter, logs and build products remain under `reverse_engineering/private/`, which Git ignores. Never stage or distribute those outputs or the supplied media.

Requires Xcode with macOS SDK, `xcodegen`, the existing Carbon Neural emulator backup at the path recorded in [Spec.md](../Spec.md), and the two workspace snapshots. The `SPECCY_BACKUP` environment variable can point to a different local copy of the same backup; its 48K ROM still must match the recorded hash. For iOS/visionOS simulator builds rather than this Mac preview, use [build.md](build.md). Neither mobile app bundles original images.
